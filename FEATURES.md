# Карта функциональных возможностей

Рабочее название: **shell**. Личный кроссплатформенный терминал (macOS, Windows, Linux) на замену Terminal.app, без аккаунтов, подписок, облака и телеметрии. Открытый код, лицензия MIT.

Работа идёт этапами. После каждого этапа терминалом можно пользоваться каждый день:
- **Этап 1** — пересесть с Terminal.app.
- **Этап 2** — ради этого всё затевается: агенты, файлы, документы, удалённые хосты.
- **Этап 3** — проекты, раскладки, глубокая связка с folio. Закрыт в 0.6.0.
- **Позже** — не отказываемся, но и не планируем на ближайшее время.

| Хоткеи | частично | полностью | полностью, есть цепочки | частично | частично | actions, полностью |
| Палитра команд | — | — | есть | есть | — | есть |

| Quake / выпадающее окно | — | Hotkey Window | Quick Terminal | есть | — | Quake mode |
| ИИ | — | плагин, ключ свой | — | встроенный, через аккаунт | — | — |
| SSH / SFTP | — | — | — | — | основная функция | — |
| Аккаунт / подписка | нет | нет | нет | **нужны** | **для синка** | нет |

Что берём у каждого:
- **Terminal.app** — нативность, аккуратный рендер шрифтов, Window Groups, ничего лишнего.
- **iTerm2** — Hotkey Window, восстановление вывода после перезапуска, Semantic History (Cmd+клик открывает файл), Arrangements, shell integration, трансляция ввода.
- **Ghostty** — скорость, конфиг-текст с hot reload, много встроенных тем, цепочки хоткеев (`ctrl+a>n`), Kitty-протоколы, приглушение неактивных панелей.
- **Warp** — команда и её вывод как единый блок. ИИ-слой и облако не берём.
- **Termius** — список хостов, SFTP-панель рядом с сессией. Без синка через их облако.
- **Windows Terminal** — модель actions + keybindings, палитра команд, цвет и переименование вкладки, запуск раскладок из CLI.
- **Midnight Commander** — двухпанельный файловый менеджер на F-клавишах, Ctrl+O прячет панели, быстрый просмотр, hotlist.

## 2. Этапы

### Этап 1 — пересесть с Terminal.app
- **Ядро эмуляции** на `@dskripchenko/terminal` (≥ 0.4.0): truecolor, Unicode, IME и русская раскладка (хоткеи работают на любой раскладке), Option как Meta, scrollback с поиском, синхронный вывод (DEC 2026), OSC 0/2, 7, 8, 52.
- **Организация:** окна → группы с цветом → вкладки с именем и цветом → сплиты (изменение размера, zoom, навигация хоткеями). Автоимя вкладки по шаблону, ручное имя приоритетнее.
- **Восстановление после перезапуска:** раскладка, папки, имена, цвета **и scrollback**. Вывод хранится в `shell-data/`, объём ограничен настройкой.
- **Выпадающее окно** по глобальному хоткею (как Hotkey Window в iTerm2).
- **Кастомизация:** конфиг-файл с hot reload, встроенные темы UID (тёмная и светлая, по системе), импорт схем iTerm2, Ghostty, Windows Terminal, base16; шрифты, курсор, отступы, профили.
- **Команды:** реестр действий с id; хоткеи с цепочками и leader-клавишей, пресеты macOS / Windows / Linux / MC, поиск конфликтов; палитра команд.
- **Строка состояния:** папка, ветка git, размер.
- **Сборка:** без установщика (zip, AppImage), `.sha256`, CI под три ОС, обновление заменой программы в её папке.

### Этап 2 — агенты, файлы, документы, удалённые хосты
- **Агенты:** пресеты запуска (claude, codex, grok…), статус на вкладке и группе (ждёт / работает / закончил / ошибка), системные уведомления, CLI `shell notify` и готовые хуки для Claude Code.
- **Панель изменений агента:** файлы, изменённые с начала сессии, отметки «просмотрено», diff, комментарий к строке уходит агенту в консоль.
- **Shell integration:** скрипты zsh, bash, fish, PowerShell (OSC 133, 7); метки команд, переход между командами, выделение вывода команды.
- **Cmd+клик по `file.ts:42`** открывает просмотрщик на строке.
- **MC-режим:** две панели поверх терминала, Ctrl+O, F3–F8, выделение по маске, быстрый просмотр, hotlist, синхронизация папки с терминалом.
- **Просмотрщик:** код с подсветкой, markdown, картинки, JSON и CSV, diff, простая правка (F4).
- **Живые блоки embed в просмотрщике:** диаграммы всех нотаций, BPMN/DMN, draw.io, OpenAPI/AsyncAPI, flow, kanban, calendar, board; отдельные файлы (`.bpmn`, `.drawio`, `.mmd`, `.puml`, `.d2`, `openapi.yaml`) своим просмотрщиком; обновление при изменении файла.
- **SSH и SFTP:** список хостов из `~/.ssh/config`, коннект в новую вкладку, SFTP в файловых панелях. Ключи — через ssh-agent и системный keychain.
- **folio, из shell в folio:** обнаружение folio, «открыть `file:line` в folio», «открыть папку как проект», «ревью работы агента в folio».

### Этап 3 — проекты и глубокая связка с folio (закрыт, 0.6.0)
- Реестр проектов, сохранённые раскладки («открыть проект» поднимает группу с агентами), нечёткий переключатель проектов. **Сделано.**

### Не берём
| Что | У кого | Почему |
|---|---|---|
| Встроенный ИИ, свои вызовы API, подсказки команд | Warp, iTerm2 | агенты — это CLI пользователя |
| Аккаунты, облачный синк, командный доступ | Warp Drive, Termius | без облака; синхронизация через dotfiles |
| Телеметрия | Warp | — |
| Свой менеджер паролей | iTerm2 | есть keychain и ssh-agent |
| Замена редактора ввода | Warp | ломает совместимость с zsh-плагинами |
| Интеграция tmux `-CC` | iTerm2 | очень сложно; tmux работает как обычная программа |
| Скриптовый API и плагины | iTerm2, WT fragments | вместо этого CLI `shell` и конфиг; вернёмся, если понадобится |
| Мобильные клиенты, serial, telnet, mosh | Termius | не наш сценарий |

## 3. Интеграция с folio (`../folio`, Electron, MIT)

folio уже умеет: md с живыми блоками и их редактирование, ревью работы агента как pull request («с последнего просмотра», worktrees, комментарии к строкам), git-историю, LSP, PDF, свои консоли, цветные группы вкладок, PostToolUse-хук Claude Code и MCP-сервер (`show_changes`, `get_review_comments`, `open_file`).

Разделение ролей: **shell** — сессии, агенты, навигация, быстрый просмотр; **folio** — правка документов, ревью, история. Без folio shell полностью работает сам; когда folio найден, появляются дополнительные возможности.

**Обнаружение.** Оба приложения портативные: без установщика, реестра и ассоциаций файлов.
- Исполняемый файл ищется так: путь из конфига shell (`[folio] path`) → файл присутствия запущенного folio → `PATH` → стандартные места (`/Applications`, `~/Applications`, рядом с shell).
- Запущенный folio оставляет файл присутствия `folio-presence.json` в `$XDG_RUNTIME_DIR` или во временном каталоге пользователя (`FOLIO_PRESENCE` — другое место): pid, версия, команда запуска, список возможностей. Файл удаляется при выходе. shell доверяет файлу, только если он принадлежит пользователю и процесс жив. Для этапа 3 сюда добавятся url и token API folio.
- Запрос передаётся аргументами командной строки: `файл:строка`, `--project <папка>`, `--review <репозиторий>`; запущенный folio получает их сам (одна копия приложения).
- Возможности согласуются по списку `capabilities`, а не по номеру версии.

**Кросс-функции**
| Функция | Направление | Этап | Что нужно |
|---|---|---|---|
| Открыть файл или `file:line` в folio | shell → folio | 2 | сделано: `файл:строка` |
| Открыть папку как проект folio | shell → folio | 2 | сделано: `--project` |
| «Ревью в folio»: рабочая копия репозитория или worktree | shell → folio | 2 | сделано: `--review` |
| Комментарии ревью в консоль агента в shell | folio → shell | 3 | API shell готов: `POST /api/paste {repo, text}` |
| «Открыть терминал здесь» в folio | folio → shell | 3 | API shell готов: `shell-presence.json`, `POST /api/open-tab {cwd, name?}` |
| Агент ждёт ответа по MCP `show_changes` → бейдж в shell | folio → shell | 3 | API shell готов: `POST /api/review {repo, state: waiting или none, message?}` |
| Кто из агентов что правил | общий | 3 | сделано: журнал `.git/agent-edits.jsonl`, один хук PostToolUse (`editsHookCommand` в `@dskripchenko/shell-integration`) |
| Темы консолей | shell → folio | 3 | сделано: `POST /api/look` — темы терминала shell (день и ночь) и шрифт; folio берёт их для своих консолей и помнит |
| Цвета групп | общий | 3 | сделано: одна палитра из 9 цветов (как группы вкладок folio) |
| Список проектов | общий | 3 | сделано: проекты folio — в его файле присутствия, shell показывает их в переключателе (и помнит); проекты shell — `POST /api/projects`, folio показывает их в палитре |
| Хоткеи | общий | 3 | сделано: одинаковые действия на одинаковых клавишах (таблица ниже), конфликт Ctrl+\` снят; файлы клавиш свои (`[keys]` shell, `keybindings.json` folio) |

**Общие хоткеи** (macOS; на Windows и Linux у shell — Ctrl+Shift, у folio — Ctrl):
| Действие | shell | folio |
|---|---|---|
| Настройки | ⌘, | ⌘, |
| Боковая панель | ⌘B | ⌘B |
| Найти | ⌘F | ⌘F |
| Новая вкладка | ⌘T | ⌘T |
| Закрыть (панель / вкладку) | ⌘W | ⌘W |
| Палитра команд | ⌘⇧P | ⌘K — в shell ⌘K очищает экран, как в Terminal.app и iTerm2; в folio ⌘⇧P — экспорт в PDF |
| Консоль / выпадающее окно | Ctrl+Alt+\` (глобально) | Ctrl+\` (в окне, как в VS Code) |

**Общий код:** скрипты интеграции с оболочками, разбор OSC-событий и журнал правок агентов — в пакете `@dskripchenko/shell-integration` (npm), им пользуются оба приложения. Установка хуков Claude Code пока своя в каждом (`claudeHooks.ts` в shell — пользовательские настройки, `review/hooks.ts` в folio — настройки репозитория).

## 4. Стек

Electron + `node-pty` + Vue 3 + `@dskripchenko/ui`, эмулятор `@dskripchenko/terminal`, просмотрщик на `@dskripchenko/code-editor`, `@dskripchenko/syntax` и `@dskripchenko/embed`. Портативная сборка и обновление — по образцу folio. Выбор эмулятора подтверждён замером (`bench/terminal`).
